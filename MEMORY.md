# Working memory

- The Question Maker new-question URL uses `QuestionComposerPage` and `ComposerMetadataFields`; changes to the older add-question dialog do not affect that route.
- Course topics created from AI Tutor and Question Maker authoring controls are written through the Core-backed topic API, then selected in the current form.
- Question Maker's shared `Toaster` has a dismiss button, and its app-level placement is top-right so it does not cover the sticky save actions.
- RAG/AI source of truth: `docs/rag-ai/README.md` indexes current chat/RAG, embeddings, routing, vLLM, testing, performance, and development-server guidance; HELPME references in `FUTURE_WORK.md` describe potential upgrades, not shipped behavior.
- Deployment source of truth: `docs/DEPLOYMENT.md` is the index for local, s378, production, inference, backup, health, and rollback guidance; `infra/inference/cmps01.md`, `cmps02.md`, and `cmps03.md` are dated host snapshots and must be revalidated after infrastructure changes.
- The course-detail manager view's staff tab reads "TAs" in the UI (#1727) but keeps `value="staff"`, `showStaffTab`, `canManageStaff`, `staffError`/`staffSuccess`, the `StaffUser` type and the `staff-tab` PICT capability id — rename display strings only, or the tab desyncs from `tests/models/course-detail-manager-view.*`.
- Bulk enrollment (#1756): CSV import and self-enrollment links both route through `addEnrollment()` in `app/lib/courses/enrollments.server.ts` — never write `prisma.enrollment` directly or you skip the `canAddEnrollmentRole` rank check. `addEnrollment` does NOT audit and does NOT enforce the instructor floor: every route logs `ENROLLMENT_ADDED` itself (single-add, CSV import, link redemption), and the floor lives in `updateEnrollmentRole`/`deactivateEnrollment`. Route through it **and log at the route**. `SelfEnrollmentLink` deliberately has NO role column so a forwarded link cannot mint staff; do not add one. Its migration (`20260916120000_add_self_enrollment_link`) was hand-written, then verified against real Postgres: `migrate deploy` applies cleanly and `migrate diff` shows the table matching `schema.prisma` exactly.
- An `INSTRUCTOR` enrollment does **not** give an ADMIN account the instructor surface. `resolveAccess` (`app/lib/auth/course-access.server.ts`) short-circuits on platform role — `if (user.role === "ADMIN") return LEVELS.admin` — and never reads the enrollment, so an ADMIN resolves to `admin`, never `instructor`. `/instructor/chat` then excludes them outright (`listMyPublishedInstructorCourses` opens with `if (user.role === "ADMIN") return []`) and redirects to `/dashboard`. That is deliberate: `/api/chat`'s instructor-mode guard resolves the same `admin` level and would 403 every turn. An in-unit UNIT_ADMIN resolves to `unit` the same way; only an out-of-unit UNIT_ADMIN falls through to the enrollment. Enrolling an admin as instructor is therefore an instructor-of-record change, not an access change (#1839/#1843).
- `docs/operations/MULTI_INSTRUCTOR_ENROLLMENT.md` is the runbook for adding a second/third instructor to an existing course; `apps/core/scripts/verify-course-instructors.ts` is its read-only verify step (service key, GET only — the enrollments POST has no service-key path because `enableSessionForAPIKeys` is false, so it needs a real ADMIN browser session on the app's own origin or the root middleware answers `403 CROSS_ORIGIN_MUTATION`).
- #1843: the admin/instructor view switch is **navigation, not stored state** — nothing is written to `UserPreference` or the session, matching AI Tutor's `StudentPreviewBanner` (#1660). `app/lib/rbac/instructor-view.server.ts` holds the whole rule: `teachesCourse(userId, courseId)` reads the enrollment `resolveAccess` short-circuits past for ADMIN/in-unit UNIT_ADMIN, and `canUseInstructorChatMode(level, isPublished, holdsEnrollment)` is the single decision shared by `/api/chat`'s gate and `/instructor/chat`'s course list. Keep those two in lockstep — #1659 introduced the old blanket ADMIN exclusion precisely because a loader and a guard had drifted, leaving a course listed that the API then 403'd on every turn.
- The old ADMIN exclusions in `instructor.chat.tsx`, `root.tsx`'s `teachingEnrollmentsPromise` and the UNIT_ADMIN unit-lock filter are all gone (#1843). Three existing tests asserted them and were deliberately reversed: `instructor-chat.route.test.ts` (2 cases) and `root-loader-parallel.test.ts` (1). An ADMIN with **no** enrollment is still denied everywhere — that half is unchanged and still covered.
